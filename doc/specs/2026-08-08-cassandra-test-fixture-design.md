# Cassandra test fixture

A local Cassandra with schema and data broad enough to develop the TUI
against. Prerequisite for the Phase 1 browse work in
[vision.md §5.1](../vision.md) and for the integration tier in
[architecture.md §10](../architecture.md).

## Shape

One node, `cassandra:5.0.8`, started by `docker/compose.yaml` and seeded by
`docker/seed.sh`. Three keyspaces, 23 tables, one materialized view, one
secondary index.

```
docker/
  compose.yaml   cassandra service + one-shot seed service
  seed.sh        applies cql/, then generates what does not belong in a file
  cql/
    00-keyspaces.cql
    10-shop-schema.cql      20-shop-data.cql
    11-typezoo-schema.cql   21-typezoo-data.cql
    12-edge-schema.cql      22-edge-data.cql
```

Files apply in filename order, so every schema precedes every data file.

`mise run db:up` starts and seeds; `db:seed`, `db:cqlsh`, `db:down`,
`db:reset` do the obvious things. The host port defaults to 9042 and is
overridable with `LC_CASSANDRA_PORT`.

## Why 5.0 and one node

5.0 is a superset of 4.1 for schema purposes, so a 5.0 fixture also covers the
older major that vision.md §300 commits to. It adds `vector<float, N>`, which
is worth having a renderer for early.

A single node keeps startup around a minute. Every keyspace is RF 1: an
unmet replication factor on one node would silently under-replicate writes.
Replication *strategy* still varies across the three keyspaces, and
`edge_cases` sets `durable_writes = false`, so the keyspace list has
properties to display.

## The three keyspaces

**`shop` — the nominal case.** Ordinary identifier lengths, realistic column
names, query-driven denormalisation: `customers_by_id`, `orders_by_customer`,
`order_items_by_order`, `products_by_category`,
`inventory_by_warehouse` (composite partition key), `product_view_counts`
(counters), plus a secondary index and the `customers_by_email` materialized
view. This is the keyspace the TUI should feel good on; the other two exist to
stop it from breaking.

`audit_log_by_day` carries the paging fixture: 2026-03-01 holds 10 000
clustering rows, with the neighbouring days deliberately small so a
partition-size contrast is visible.

**`typezoo` — value coverage.** One table per type family, so a rendering bug
points at a type rather than at a table: every CQL scalar; collections
including frozen and nested-frozen; UDTs including a nested UDT and UDTs
inside collections; tuples; `vector<float, 3>` and `vector<float, 384>`;
static columns, including a partition holding *only* its static columns; and
`nulls_and_empties`, which separates never-written from explicitly-null from
empty-but-present.

**`edge_cases` — identifier and shape torture.** 48-character names,
single-character names, quoted `"CamelCase"`, quoted CQL reserved words,
non-ASCII and emoji column names, a 100-column table, a partition-key-only
table, and a four-component partition key with three mixed-order clustering
columns.

`hostile_values` holds what breaks terminals rather than parsers: raw ANSI
escape sequences, C0 control characters, double-width CJK, RTL text with an
explicit override, combining marks and zero-width joiners, a 100 KB text and a
64 KB blob. A grid that writes cell contents straight to the terminal will
repaint in red and clear the screen when row 1 scrolls past — that is the
point of the row.

## Determinism and idempotency

The fixture holds to the same rule as the fast test tiers
([conventions.md](../conventions.md)): no `now()`, no `uuid()`, no `$RANDOM`,
no wall clock. Every UUID, timeuuid and timestamp is a literal, and the
generated rows derive their values arithmetically from the row index. Two runs
against empty volumes produce identical data.

All DDL is `IF NOT EXISTS` and every `INSERT` is an upsert on a literal
primary key, so re-seeding a populated volume is a no-op — with one exception.
A counter `UPDATE` is an increment, not an upsert, and counter tables admit no
lightweight transaction, so `product_view_counts` is seeded from `seed.sh`
behind an explicit read guard rather than from `20-shop-data.cql`. Replaying
that file would multiply the totals by the number of runs.

Three things are generated by `seed.sh` rather than checked into `cql/`:

- the 10 000-row wide partition, which would be a 2 MB file
- the 384-dimension vector, which would be a 3 KB single-line literal
- the hostile values, which need raw ESC and C0 bytes that an editor mangles

## Constraints found while building this

Worth recording, because each one bounds what the TUI has to handle:

- **Table and keyspace names are `[A-Za-z0-9_]` only**, since the name becomes
  a directory on disk. Column names are unrestricted quoted identifiers —
  emoji, spaces and CJK all work. The unicode table in `edge_cases` is
  therefore ASCII-named with hostile columns.
- **A single-component partition key rejects the empty string** with "Key may
  not be empty". A composite partition key accepts empty components.
- **48 characters** is the hard limit for keyspace, table and column names.
- **Materialized views ship disabled** (`materialized_views_enabled: false`).
  The compose `command` flips the flag before the entrypoint reads
  `cassandra.yaml`.
- **`cqlsh -e` mishandles statements spanning multiple lines**, reporting a
  spurious trailing syntax error. Everything goes through `-f`.

## Out of scope

UDFs, which need a second config override for little navigational value, and
SAI vector indexes — the plain `vector` columns cover type rendering, and the
index only matters once ANN queries exist.
